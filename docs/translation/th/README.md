## 1. วิสัยทัศน์และขอบเขต

Omega-track ตอบสองคำถาม: “เป้าหมายนี้คือใคร?” (อัตลักษณ์จาก RDAP/DNS/ใบรับรอง/ชื่อเสียง) และ “ไปถึงที่นั่นได้อย่างไร?” (เส้นทางเครือข่าย NeoTrace, GeoIP, ASN) มันเสริม `omega-check` (การเปิดเผยทางเครือข่าย) `omega-scan` (สุขอนามัย HTTP/HTTPS) และ `omega-deep` (การวิเคราะห์สถาปัตยกรรมแบบมีขอบเขต) โดยไม่ซ้ำซ้อนกับเครื่องมือเหล่านั้น

### สิ่งที่ Omega-track ทำ

- รับเป้าหมายเป็น IP, IPv6 หรือชื่อโดเมน บันทึกไว้และปักหมุดได้ตามต้องการ (การอนุญาตแบบถาวร)
- รวบรวมข้อมูลสาธารณะ แบบพาสซีฟหรือที่โปรไฟล์เปิดใช้อย่างชัดเจน (RDAP, DNS, Certificate Transparency, คลังข้อมูล Wayback, ประกาศ BGP)
- รัน traceroute แบบเสริมข้อมูลสไตล์ NeoTrace (การกระทำทางเครือข่ายเชิงรุกเพียงอย่างเดียวในแกนของผลิตภัณฑ์)
- เสริมข้อมูลให้แต่ละ IP ที่เกี่ยวข้องด้วยฐานข้อมูล GeoIP ในเครื่อง (DB-IP Lite ไม่ต้องใช้คีย์ หรือ MaxMind GeoLite2 แบบเลือกได้ที่ใช้คีย์)
- สอบถามแหล่งข้อมูลชื่อเสียง (VirusTotal, HIBP) ด้วยคีย์ที่ผู้ใช้ให้มา โดยเปิดเผยโควตาและข้อมูลที่ส่งทุกครั้งก่อนเปิดใช้
- เชื่อมโยงข้อมูลที่สังเกตได้ให้เป็นโปรไฟล์ที่สอดคล้องกัน พร้อมระดับความเชื่อมั่นที่ชัดเจนสำหรับทุกข้อมูล
- เก็บเป้าหมาย การรัน ผลลัพธ์ ข้อผิดพลาด และการส่งออกไว้ในเครื่อง (SQLite, `./var/`)
- มี TUI ของ Textual และ CLI ที่ทำงานได้เท่าเทียมกันอย่างเคร่งครัด
- สร้างรายงาน HTML (5 ธีม พร้อมกราฟความสัมพันธ์ Mermaid ฝังในตัว) JSON, Markdown, CSV และไฟล์ DOT และ Mermaid แบบแยกอิสระ

### สิ่งที่ Omega-track ไม่ทำ

| ฟังก์ชัน | เครื่องมือที่รับผิดชอบ |
|---|---|
| การสแกนพอร์ต การระบุบริการและแบนเนอร์ | OMEGA-CHECK |
| การตรวจ HTTP/HTTPS, header, TLS, สุขอนามัยเว็บ | OMEGA-SCAN |
| การครอว์ล การท่องสถาปัตยกรรม และการเจาะลงไปยังเป้าหมายที่เชื่อมโยง | OMEGA-DEEP |
| การครอว์ลระยะไกลทีละหน้า (ลิงก์ ไฟล์) | OMEGA-FOLD |
| การทดสอบโหลด | OMEGA-STRESS |
| Fuzzing และการทดสอบความทนทานของแอปพลิเคชัน | OMEGA-FUZZ |

สิ่งที่ควรหลีกเลี่ยง รวมถึงนอกเหนือ MVP: brute-force โดเมนย่อย การสแกนพอร์ต การครอว์ลเว็บ การเก็บข้อมูลส่วนบุคคลแบบล่วงล้ำ การหลบเลี่ยงการป้องกันแบบอัตโนมัติ การ scraping ที่เปราะบางบนแพลตฟอร์มที่ต้องยืนยันตัวตน การค้นหาบุคคล/โซเชียลเน็ตเวิร์ก/pastebin-ข้อมูลรั่วไหล การเฝ้าติดตามเป้าหมายเป็นระยะ/ซ้ำ ๆ (ดู `docs/PRODUCT_SCOPE.md` §7 "เลื่อนออกไปโดยเจตนา")

### คำเตือนเรื่องการใช้งานที่ได้รับอนุญาต

Omega-track เป็นเครื่องมือสืบสวนเครือข่ายสำหรับการใช้งานที่ชอบธรรม: ตรวจสอบโครงสร้างพื้นฐานของคุณเอง รับมือเหตุการณ์ด้านความปลอดภัย เฝ้าดูขอบเขตที่คุณได้รับอนุญาตให้บันทึกข้อมูล การเก็บข้อมูลแทบทั้งหมดเป็นแบบพาสซีฟ/สาธารณะ (RDAP, DNS, บันทึก CT — ข้อมูลที่เป้าหมายหรือผู้รับจดทะเบียนเปิดเผยต่อสาธารณะอยู่แล้ว) ยกเว้น traceroute (เชิงรุกเล็กน้อย และแสดงในโปรไฟล์ที่ใช้เสมอ)

**ไม่มีการสังเกตใดเริ่มบนเป้าหมายที่ไม่ได้ปักหมุดหากไม่มีการยืนยันอย่างชัดเจน** (`--authorize` ใน CLI, การยืนยันใน TUI) คุณเป็นผู้รับผิดชอบแต่เพียงผู้เดียวในการตรวจสอบว่าการใช้งานของคุณเป็นไปตามกฎหมายที่ใช้บังคับและเงื่อนไขการใช้งานของแหล่งข้อมูลภายนอกที่สอบถาม

## 2. การติดตั้ง

### ข้อกำหนดเบื้องต้น

- Python 3.10+
- การเชื่อมต่ออินเทอร์เน็ต สำหรับส่วนที่ต้องพึ่งพาและแหล่งข้อมูลพาสซีฟที่สอบถาม
- ติดตั้ง `traceroute` หรือ `tracepath` แล้ว (โมดูล NeoTrace) — หากไม่มีจะลดระดับอย่างเรียบร้อย ส่วนอื่นของเครื่องมือยังทำงานตามปกติ

### การติดตั้ง

```bash
[ -d omega-track ] && echo "ℹ️ แตกไฟล์ไว้ที่นี่แล้ว ข้ามขั้นตอนนี้" || tar -xzf omega-track.tar.gz
cd omega-track/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. สร้างสภาพแวดล้อมเสมือน `.venv` หากยังไม่มี
2. ติดตั้งส่วนที่ต้องพึ่งพา (`pip install -e .`, `pyproject.toml` ยังคงเป็นแหล่งข้อมูลหลักเพียงแหล่งเดียว)
3. ทำให้ `omega-track.sh` และ `install.sh` เรียกใช้งานได้
4. เพิ่มชื่อแทน `track` ลงใน `~/.bashrc` และ `~/.zshrc` (ไม่เพิ่มซ้ำหากมีอยู่แล้ว)

### ส่วนที่ต้องพึ่งพา

ประกาศไว้ใน `pyproject.toml` (ไม่มี `requirements.txt` แยก):
- `omega-lib`: ไลบรารีที่ใช้ร่วมกันของชุดเครื่องมือ (`ConfidenceLevel`, ธีม, การตรวจจับเทอร์มินัล)
- `textual`: อินเทอร์เฟซ TUI ธีม การปรับให้เข้ากับเทอร์มินัลโดยอัตโนมัติ
- `dnspython`: การแปลง DNS แบบไปข้างหน้าและย้อนกลับ
- `httpx`: ตัวตรวจ RDAP/CT/คลังข้อมูล/BGP/VirusTotal/HIBP
- `maxminddb`: อ่านฐานข้อมูล GeoIP ในเครื่อง (DB-IP Lite, MaxMind GeoLite2)
- `jinja2`: เทมเพลตสำหรับการส่งออก HTML
- ส่วนที่ต้องพึ่งพาสำหรับการพัฒนา (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `pytest-cov`, `pytest-httpserver`, `ruff`, `mypy`, `import-linter`

## 3. การใช้งาน

### โหมดโต้ตอบ (TUI)

แนะนำสำหรับการใช้งานประจำวัน — เปิดโดยไม่มีอาร์กิวเมนต์:

```bash
./omega-track.sh
```
หากสร้างชื่อแทนไว้แล้ว เพียงพิมพ์ `track` ในเทอร์มินัล:
```bash
track
```

ลำดับการใช้งาน: หน้าจอเปิด (ปิดเมื่อกดแป้นหรือคลิก) → เมนูหลัก (เป้าหมาย / Tracker / ผลลัพธ์ / ประวัติ / แดชบอร์ด / GeoIP / แหล่งข้อมูลที่ใช้คีย์ / การตั้งค่า / ช่วยเหลือ) → กรอกหรือเลือกเป้าหมาย (ยืนยันอย่างชัดเจนหากยังไม่ได้ปักหมุด) และเลือกโมดูลการเก็บข้อมูล → การสังเกต (มาตรวัดและลำดับการทำงานแบบสด ยกเลิกได้) → ผลลัพธ์โดยละเอียดแยกตามแท็บ (ตัวตน/DNS/เครือข่าย / ASN/NeoTrace/ใบรับรอง/คลังข้อมูล/ความสัมพันธ์/การวินิจฉัย, การส่งออก) → ประวัติ/แดชบอร์ด/การตั้งค่าจากเมนูหลัก การปรับให้เข้ากับเทอร์มินัล (สี ขนาด การลดทอนโครงสร้าง) เป็นไปโดยอัตโนมัติ

### ภาษาของอินเทอร์เฟซ

อินเทอร์เฟซมีให้ใช้ 17 ภาษา: ฝรั่งเศส อังกฤษ สเปน โปรตุเกส (บราซิล) อิตาลี เยอรมัน ดัตช์ โปแลนด์ รัสเซีย จีนตัวย่อ เวียดนาม ไทย อินโดนีเซีย ญี่ปุ่น เกาหลี ฮินดี และอาหรับ เลือกได้ในการตั้งค่า (“Langue / Language”) และมีผลหลังจากรีสตาร์ตอินเทอร์เฟซ ตัวแปร `OMEGA_TRACK_LANG` (เช่น `OMEGA_TRACK_LANG=th ./omega-track.sh`) ใช้บังคับภาษาสำหรับหนึ่งเซสชัน เมื่อเปิดจาก omega-suite แล้ว omega-track จะใช้ภาษาของชุดเครื่องมือ บนคอนโซลข้อความของ Linux (TTY) ภาษาที่ไม่ได้ใช้อักษรละตินจะแสดงเป็นภาษาอังกฤษตลอดเซสชันนั้น บรรทัดคำสั่งยังคงเป็นภาษาฝรั่งเศส

### ติดต่อและสนับสนุน

ความช่วยเหลือ (ปุ่ม `a`) มีหน้าจอ **ติดต่อและสนับสนุน**: *เลี้ยงกาแฟ* (หน้า PayPal ของผู้พัฒนา), *ติดต่อฝ่ายสนับสนุน* (ที่อยู่อีเมลและแบบฟอร์มติดต่อของเว็บไซต์ แสดงเป็นข้อความธรรมดา), *ลงทะเบียนเป็นผู้ใช้ (นิรนาม)* และ *ตรวจสอบการอัปเดต* การลงทะเบียนเป็นไปโดยสมัครใจ ปิดไว้เป็นค่าเริ่มต้น และส่งเพียงครั้งเดียว ใช้เพื่อนับจำนวนผู้ใช้เท่านั้น และหากต้องการ นับทวีปหรือประเทศของผู้ใช้ (รายการปิด ไม่มีข้อความอิสระ) ระบบจะส่งคีย์ที่สุ่มขึ้น ชื่อซอฟต์แวร์ (`omega-track`) และเวอร์ชัน ไม่ส่งชื่อ ชื่อเครื่อง การตั้งค่า เป้าหมาย หรือผลลัพธ์ใด ๆ ที่อยู่ IP จะไม่ถูกบันทึกในการลงทะเบียน แต่เช่นเดียวกับการเข้าชมทุกครั้ง จะผ่านการตรวจสอบความปลอดภัยและบันทึกของเซิร์ฟเวอร์ที่รับข้อมูล ถอนการลงทะเบียนได้ทุกเมื่อจากหน้าจอเดียวกัน (*ไม่ต้องลงทะเบียนฉันอีก*) การตรวจสอบการอัปเดตเพียงอ่านรายการเวอร์ชันที่เผยแพร่บนเว็บไซต์ และไม่ทำโดยไม่มีการคลิก

### โหมดเขียนสคริปต์ (CLI)

คำสั่งย่อยใดก็ตามจะเปิดโหมด CLI:

```bash
# เป้าหมาย
./omega-track.sh target add example.org --alias "เว็บไซต์หน้าร้าน" --tag prod
./omega-track.sh target list
./omega-track.sh target pin <target_id>

# เริ่มและติดตามการสังเกต
./omega-track.sh track run <target_id> --module dns --module rdap --module neotrace --authorize
./omega-track.sh track status <run_id>
./omega-track.sh track show <run_id>
./omega-track.sh track replay <run_id> --authorize

# ประวัติ
./omega-track.sh history list --target <target_id> --status completed --since 2026-01-01

# การส่งออก — 6 รูปแบบ 5 ธีมสำหรับ HTML
./omega-track.sh export <run_id> --format html --theme omega-neon --redact contacts_only

# GeoIP
./omega-track.sh geoip status
./omega-track.sh geoip update --provider dbip

# แหล่งข้อมูลชื่อเสียงที่ใช้คีย์ (แสดงการเปิดเผยข้อมูลก่อนการบันทึกใด ๆ)
./omega-track.sh source list
./omega-track.sh source info virustotal
./omega-track.sh source configure virustotal <คีย์_api>

# การตั้งค่าและการล้าง
./omega-track.sh config show
./omega-track.sh cleanup preview --older-than 30
./omega-track.sh cleanup run --older-than 30 --yes

# การวินิจฉัยในเครื่อง (เวอร์ชัน ความสามารถ เส้นทาง สถานะ GeoIP)
./omega-track.sh diagnostics
```

ทุกคำสั่งย่อยรับ `--json` เพื่อให้ได้เอาต์พุตที่เครื่องอ่านได้อย่างเคร่งครัด

#### รหัสออก

| รหัส | ความหมาย |
|---:|---|
| `0` | สำเร็จ (การสังเกตเสร็จสิ้น, `COMPLETED`) |
| `1` | ข้อผิดพลาดในการตรวจสอบ (เป้าหมายไม่ถูกต้อง รูปแบบการส่งออกที่ไม่รู้จัก การเปลี่ยนสถานะที่ไม่ถูกต้อง ไม่มีคีย์ API...) |
| `2` | เป้าหมายไม่ได้รับอนุญาต (ไม่ได้ปักหมุด และไม่มี `--authorize`) |
| `3` | ไม่พบทรัพยากรหรือแหล่งข้อมูลไม่พร้อมใช้งาน (เป้าหมาย/การรันที่ไม่รู้จัก ดาวน์โหลด GeoIP ล้มเหลว) |
| `4` | การสังเกตบางส่วน (`PARTIAL`) — ไม่ใช่ความล้มเหลว มีเพียงบางโมดูลที่สำเร็จ |
| `5` | ข้อผิดพลาดภายในที่ไม่คาดคิด |
| `130` | ผู้ใช้ขัดจังหวะ (`Ctrl+C`) |

### รูปแบบเป้าหมายที่รองรับ

```text
192.168.1.10                IPv4
2001:db8::1                 IPv6
example.org                 โดเมน
```

## 4. โมดูลการเก็บข้อมูล

| โมดูล | โหมดการเก็บข้อมูล | เปิดเป็นค่าเริ่มต้น | ต้องใช้คีย์ |
|---|---|:---:|:---:|
| `dns` | เชิงรุกเล็กน้อย (การแปลงไปข้างหน้า) | ใช่ | ไม่ |
| `reverse_dns` | เชิงรุกเล็กน้อย (PTR) | ใช่ | ไม่ |
| `rdap` | พาสซีฟสาธารณะ | ใช่ | ไม่ |
| `neotrace` | เชิงรุกเล็กน้อย (traceroute/tracepath) | ใช่ | ไม่ |
| `certificate_transparency` | พาสซีฟสาธารณะ (`crt.sh`) | ไม่ | ไม่ |
| `archives` | พาสซีฟสาธารณะ (Wayback Machine) | ไม่ | ไม่ |
| `bgp` | พาสซีฟสาธารณะ (RIPEstat) | ไม่ | ไม่ |
| `virustotal` | ใช้คีย์ของผู้ใช้ | ไม่ | ใช่ (ฟรี) |
| `hibp` | ใช้คีย์ของผู้ใช้ | ไม่ | ใช่ (**เสียค่าใช้จ่าย** ตั้งแต่ปี 2022) |

สี่โมดูลแรกเป็นฐานของ MVP (`dns`/`reverse_dns`/`rdap`/`neotrace`) และถูกติ๊กไว้เป็นค่าเริ่มต้นในแบบฟอร์มเริ่มต้น ส่วนห้าโมดูลถัดมาเป็นทางเลือกและต้องเปิดใช้อย่างชัดเจน แหล่งข้อมูลที่ไม่ได้กำหนดคีย์จะไม่ทำให้การสังเกตล้มเหลว: โมดูลที่เกี่ยวข้องเพียงเปลี่ยนเป็น `SKIPPED` (“ไม่ได้รัน”) รายละเอียดของแต่ละแหล่ง โควตา และสัญญาอนุญาต: `docs/DATA_SOURCES.md`

## 5. สถาปัตยกรรม

Omega-track จัดโครงสร้างตาม **Clean Architecture** (domain / application / infrastructure / interfaces / ports / core / app / plugins) สอดคล้องกับแม่แบบของชุด `omega-` (ดู `omega-check`/`omega-fold`) และตรวจสอบด้วย `import-linter` ทุกครั้งที่มีการแก้ไข

```text
src/omega_track/
├── domain/          ตรรกะทางธุรกิจล้วน (เป้าหมาย, TrackRun/ModuleRun, findings, ความสัมพันธ์, โปรไฟล์...)
├── application/     กรณีการใช้งาน (commands/queries/ตัวประสานช่วง/นโยบาย)
├── ports/           สัญญาที่แอปพลิเคชันคาดหวัง (ตัวเก็บข้อมูล ที่เก็บข้อมูล ตัวส่งออก...)
├── infrastructure/  การทำงานจริง (dnspython/httpx/subprocess/maxminddb, SQLite, jinja2)
├── interfaces/      tui/ (Textual) และ cli/ (เขียนสคริปต์ได้) ความสามารถเท่าเทียมกันอย่างเคร่งครัด
├── app/             การประกอบ (DependencyContainer, การเริ่มระบบ, วงจรชีวิต)
├── core/            คำศัพท์ร่วม (เวอร์ชัน, การส่งออกซ้ำจาก omega-lib)
└── plugins/         โมดูลเสริมแบบแหล่งเดียว (CT, คลังข้อมูล, BGP, VirusTotal, HIBP)
```

กฎการออกแบบ:
- `domain/` ไม่เคยทำงานด้านเครือข่ายหรือ I/O ส่วน `infrastructure/` ทำงานด้านเครือข่ายและ I/O แต่ไม่เคยตัดสิน
- `interfaces/` แสดงผลและไม่มีตรรกะทางธุรกิจใด ๆ — CLI และ TUI เรียกกรณีการใช้งานเดียวกันอย่างเคร่งครัด
- 1 โมดูลการเก็บข้อมูล = 1 แหล่ง = 1 สถานะ (`ModuleRun`): ไม่เคยรวมสองแหล่งไว้ใต้สถานะเดียวที่กำกวม
- การขาดช่องข้อมูลเพียงช่องเดียวไม่เคยถือเป็นข้อผิดพลาด มีเพียงการที่แหล่งข้อมูลใช้งานไม่ได้ทั้งหมดเท่านั้นที่ทำให้เกิด `SKIPPED`/`FAILED`

## 6. แหล่งข้อมูล

| แหล่ง | ผู้ให้บริการ | คีย์ | โหมด |
|---|---|:---:|---|
| DNS ไปข้างหน้า/ย้อนกลับ | ตัวแปลงชื่อของระบบ | ไม่ | เชิงรุกเล็กน้อย |
| RDAP | Bootstrap ของ IANA → RIR/ผู้รับจดทะเบียน | ไม่ | พาสซีฟสาธารณะ |
| Certificate Transparency | `crt.sh` (Sectigo) | ไม่ | พาสซีฟสาธารณะ |
| คลังข้อมูลเว็บ | Wayback Machine (Internet Archive) | ไม่ | พาสซีฟสาธารณะ |
| BGP / ประกาศเครือข่าย | RIPEstat (RIPE NCC) | ไม่ | พาสซีฟสาธารณะ |
| GeoIP | DB-IP Lite (ค่าเริ่มต้น) หรือ MaxMind GeoLite2 | ไม่ / ใช่ | ออฟไลน์ (ฐานข้อมูลในเครื่อง) |
| NeoTrace | `traceroute`/`tracepath` ในเครื่อง | ไม่ | เชิงรุกเล็กน้อย |
| ชื่อเสียง | VirusTotal | ใช่ (ฟรี) | ใช้คีย์ |
| ชื่อเสียง | Have I Been Pwned | ใช่ (เสียค่าใช้จ่าย) | ใช้คีย์ |

โควตา สัญญาอนุญาต และทางเลือกสำรองที่แน่นอนของแต่ละแหล่ง: `docs/DATA_SOURCES.md` ไม่มีคีย์ API ใดปรากฏในบันทึก การส่งออก หรือหน้าจอวินิจฉัยเลย

## 7. นโยบายความเชื่อมั่น

ทุกช่องข้อมูลที่เก็บได้จะมีหนึ่งในระดับต่อไปนี้ (ใช้ร่วมกับทั้งชุดเครื่องมือผ่าน `omega-lib`):

| ระดับ | ความหมาย |
|---|---|
| `VERIFIED` | ข้อเท็จจริงของโปรโตคอลที่สังเกตได้โดยตรง ซึ่งเป้าหมายปลอมแปลงไม่ได้ (เช่น คำตอบ DNS โดยตรง การวัด traceroute ในเครื่อง) |
| `DECLARED` | ค่าที่แหล่งข้อมูลประกาศเองในช่องที่ตนควบคุมได้ทั้งหมด (เช่น ข้อมูล RDAP ที่ผู้รับจดทะเบียนแสดง) — น่าเชื่อถือแต่ปลอมแปลงได้ตามใจ |
| `CORROBORATED` | ค่า `DECLARED` ที่ได้รับการยืนยันจากหลักฐานอิสระ (เช่น โดเมนที่พบในบันทึก Certificate Transparency อย่างน้อยสองแหล่งที่ต่างกัน) |
| `INFERRED` | อนุมานจากรูปแบบ/ฮิวริสติก โดยไม่มีการประกาศอย่างชัดเจน (เช่น ASN ร่วมที่ใช้ชี้ถึงความสัมพันธ์ ไม่เคยถูกเลื่อนระดับโดยอัตโนมัติ) |
| `UNKNOWN` | ไม่มีหลักฐานที่ใช้ได้ หรือถูกเป้าหมายซ่อนไว้โดยเจตนา |

คะแนนความเชื่อมั่นโดยรวมของการสังเกตเป็นเครื่องช่วยในการอ่าน ไม่ใช่คำตัดสินด้านความปลอดภัย

## 8. ระดับการเก็บข้อมูล การอนุญาต และการปกปิดข้อมูล

ทุกโปรไฟล์ระบุลักษณะของการกระทำอย่างชัดเจน (`CollectionMode`):

- **ออฟไลน์**: ตรวจสอบเป้าหมาย อ่าน GeoIP ในเครื่อง เชื่อมโยงข้อมูลที่เก็บไว้แล้ว การส่งออก — ไม่ใช้เครือข่าย
- **พาสซีฟสาธารณะ**: RDAP, DNS สาธารณะ, บันทึก CT, คลังข้อมูล, BGP — ส่งเพียงเป้าหมายที่สอบถามไปยังบุคคลที่สาม ซึ่งเป็นคุณสมบัติโดยธรรมชาติของโปรโตคอล
- **เชิงรุกเล็กน้อย**: การแปลง DNS, DNS ย้อนกลับ, traceroute — ตัวแปลงชื่อที่ตั้งค่าบนเครื่องและเราเตอร์ตัวกลางทุกตัวบนเส้นทางจะเห็นคำขอ
- **ใช้คีย์ของผู้ใช้**: ผู้ให้บริการที่ต้องใช้คีย์หรือกำหนดโควตา เปิดใช้ได้หลังจากกำหนดค่าอย่างชัดเจนและแสดงการเปิดเผยข้อมูล (โควตา ข้อมูลที่ส่ง) แล้วเท่านั้น

**ตัวป้องกันการอนุญาต**: ไม่มีการสังเกตใดเริ่มบนเป้าหมายที่ไม่ได้ปักหมุดหากไม่มีการยืนยันอย่างชัดเจน (`--authorize` ใน CLI, ช่องติ๊กใน TUI) การปักหมุดเป้าหมายจะอนุญาตเป้าหมายนั้นอย่างถาวรสำหรับการสังเกตในอนาคต

**การปกปิดข้อมูลในการส่งออก**: ทุกการส่งออกรับนโยบาย (`none`/`contacts_only`/`sensitive_only`/`strict`) ที่ซ่อนช่องข้อมูลอ่อนไหว (โดยเฉพาะข้อมูลติดต่อ RDAP) ในผลลัพธ์ที่ส่งออก — ส่วนที่เก็บข้อมูลในเครื่องยังคงเก็บข้อมูลที่รวบรวมได้ครบถ้วนเสมอ รายละเอียด: `docs/PRIVACY.md`

## 9. ความเข้ากันได้กับเทอร์มินัล

TUI (Textual) ตรวจจับความสามารถของเทอร์มินัล (อีมูเลเตอร์ ขนาด) โดยอัตโนมัติ และปรับสไตล์ชีตเชิงโครงสร้างตามนั้น (`complete`/`standard`/`reduced`/`mono`) โดยไม่ต้องใช้แฟล็กด้วยมือ โหมด CLI ยังคงเป็นข้อความธรรมดาเสมอ ไม่ขึ้นกับเทอร์มินัล นโยบายนี้ใช้ร่วมกันทั้งชุด `omega-` (`omega-lib`, `terminal/policies.py`)

### โปรไฟล์ตามอีมูเลเตอร์ที่ตรวจพบ

| อีมูเลเตอร์ | โปรไฟล์เริ่มต้น |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, SSH รุ่นใหม่ | `reduced` |
| TTY ของ Linux, SSH รุ่นเก่า | `mono` |
| อีมูเลเตอร์ที่ไม่รู้จัก | `reduced` (ค่าสำรองเริ่มต้น) |

### โปรไฟล์ตามขนาดเทอร์มินัล

| ขนาดขั้นต่ำ (คอลัมน์ × บรรทัด) | เพดานโปรไฟล์ |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| ต่ำกว่านั้น | `mono` |

โปรไฟล์สุดท้ายที่ใช้คือ **แบบที่เข้มงวดกว่าในสองแบบ** (อีมูเลเตอร์และขนาด) รีเฟรชแบบสดได้ด้วยแป้น `r`

## 10. การส่งออก

รายงาน Markdown และ HTML เขียนด้วยภาษาที่เลือกในการตั้งค่า (“ภาษาของการส่งออก” ค่าเริ่มต้นคือภาษาของอินเทอร์เฟซ) ส่วน JSON, CSV, DOT และ Mermaid ยังคงเป็นข้อมูลและไม่ถูกแปล รายงานสร้างใน `var/exports/` เป็นค่าเริ่มต้น (เส้นทางขณะรันที่ยึดกับโฟลเดอร์โปรเจกต์ ใช้ `$OMEGA_TRACK_VAR_DIR` เพื่อเปลี่ยน) หรือที่เส้นทางที่ระบุ (`--output` ใน CLI, กล่องโต้ตอบใน TUI) ชื่อไฟล์ไม่ซ้ำพร้อมเวลากำกับ: `{เวลา}_{เป้าหมาย}_{id_สั้น}.{นามสกุล}`

| รูปแบบ | เนื้อหา |
|---|---|
| `json` | โครงสร้างครบถ้วนของการสังเกต (`TrackRun` + findings + ความสัมพันธ์) แหล่งข้อมูลหลัก แปลงเป็น JSON ได้อย่างเคร่งครัด |
| `markdown` | รายงานกระชับสำหรับมนุษย์ อ่านได้นอกเทอร์มินัล |
| `html` | รายงานเว็บแบบแยกอิสระ เลือกได้ 5 ธีม (`--theme`) พร้อมกราฟความสัมพันธ์ Mermaid ฝังในตัว |
| `csv` | หนึ่งตารางต่อหนึ่งหมวดหมู่ของ finding |
| `dot` | กราฟความสัมพันธ์ Graphviz ไฟล์แยกอิสระ |
| `mermaid` | กราฟความสัมพันธ์ Mermaid ไฟล์แยกอิสระ |

## 11. ประวัติ การล้าง และการรันซ้ำ

ทุกการสังเกตถูกบันทึกไว้ (SQLite, `var/db/omega-track.db`): ประวัติที่เรียกดูและกรองได้ (เป้าหมาย/สถานะ/แท็ก/ช่วงเวลา) แดชบอร์ดสรุป (การแจกแจงตามสถานะ ความน่าเชื่อถือของแต่ละโมดูล ประเภทของ findings ล่าสุด) การรันการสังเกตซ้ำบนเป้าหมายเดิมโดยไม่ต้องกรอกใหม่ (`track replay`) และการล้างประวัติเก่าพร้อมการแสดงตัวอย่างทุกครั้งก่อนลบ (`cleanup preview` ก่อน `cleanup run --yes`)

## 13. นอกขอบเขต

- ประวัติ WHOIS/DNS แบบครบถ้วน passive DNS เชิงพาณิชย์
- การค้นหาบุคคล โซเชียลเน็ตเวิร์ก pastebin/ข้อมูลรั่วไหล
- การสแกนพอร์ต การระบุบริการและแบนเนอร์ (`omega-check`)
- การตรวจ HTTP/HTTPS, header, TLS (`omega-scan`)
- การครอว์ลและการท่องสถาปัตยกรรม (`omega-deep`/`omega-fold`)
- การทดสอบโหลด (`omega-stress`), fuzzing (`omega-fuzz`)
- แผนที่แบบโต้ตอบใน TUI (สงวนไว้สำหรับรายงาน HTML ที่ส่งออก)
- MTR แบบต่อเนื่อง หลายตัวตรวจ และหลายจุดสังเกต
- โหมดแบตช์/เป็นระยะ/การเฝ้าติดตามเป้าหมายซ้ำ ๆ — `TrackRun` ยังคงเป็นการกระทำด้วยมือที่ชัดเจนเสมอ
- เอนจินย้ายสคีมา SQLite (สคีมาแบบเพิ่มเติม แนวปฏิบัติเดียวกับส่วนอื่นของชุดเครื่องมือ)
