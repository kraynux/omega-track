**Omega-track** — это TUI + CLI инструмент, который строит по IP, IPv6 или домену максимально полную цифровую идентичность: кто стоит за этой целью, как до неё добраться и с какой степенью достоверности можно считать каждую собранную информацию установленным фактом. Шестой инструмент набора `omega-` (после `omega-fire`, `omega-stress`, `omega-scan`, `omega-check` и `omega-deep`/`omega-fold`), построенный по принципам Clean Architecture; полное описание — в `docs/PRODUCT_SCOPE.md` и `docs/DATA_SOURCES.md`.

## 1. Назначение и границы

Omega-track отвечает на два вопроса: «кто эта цель?» (идентификация через RDAP/DNS/сертификаты/репутацию) и «как до неё добраться?» (сетевой маршрут через NeoTrace, GeoIP, ASN). Он дополняет `omega-check` (сетевая экспозиция), `omega-scan` (гигиена HTTP/HTTPS) и `omega-deep` (ограниченный анализ архитектуры), не дублируя их.

### Что делает Omega-track

- Принимает цель — IP, IPv6 или домен, регистрирует её и опционально закрепляет (постоянная авторизация).
- Централизует публичные, пассивные или явно включённые сведения (RDAP, DNS, Certificate Transparency, архивы Wayback, анонсы BGP).
- Выполняет расширенный traceroute в стиле NeoTrace (единственное активное сетевое действие ядра продукта).
- Обогащает каждый релевантный IP через локальную базу GeoIP (DB-IP Lite без ключа, MaxMind GeoLite2 опционально с ключом).
- Опрашивает, при наличии ключа, предоставленного пользователем, источники репутации (VirusTotal, HIBP), с обязательным раскрытием условий (квота, отправляемые данные) перед любой активацией.
- Связывает наблюдаемые данные в единый профиль, с явным уровнем достоверности для каждого элемента.
- Хранит цели, запуски, результаты, ошибки и экспорты локально (SQLite, `./var/`).
- Предоставляет TUI на Textual и CLI, строго функционально эквивалентные.
- Формирует отчёты HTML (5 тем, встроенный граф связей Mermaid), JSON, Markdown, CSV и автономные графы DOT и Mermaid.

### Чего Omega-track не делает

| Функция | Ответственный инструмент |
|---|---|
| Сканирование портов, определение служб и баннеров | OMEGA-CHECK |
| Проверки HTTP/HTTPS, заголовков, TLS, гигиены веба | OMEGA-SCAN |
| Обход и анализ архитектуры, переход к связанным целям | OMEGA-DEEP |
| Постраничный удалённый обход (ссылки, файлы) | OMEGA-FOLD |
| Нагрузочное тестирование | OMEGA-STRESS |
| Фаззинг и тестирование устойчивости приложений | OMEGA-FUZZ |

Чего следует избегать, в том числе за пределами MVP: перебор поддоменов, сканирование портов, обход веб-страниц, интрузивный сбор персональных данных, автоматизация обхода защит, хрупкий скрапинг платформ, требующих аутентификации, поиск людей/соцсетей/pastebin-утечек, периодическое/повторяющееся наблюдение за целью (см. `docs/PRODUCT_SCOPE.md` §7 «Сознательно отложено»).

### Предупреждение об авторизованном использовании

Omega-track — инструмент сетевого расследования, предназначенный для законного использования: аудит собственной инфраструктуры, реагирование на инциденты, наблюдение за периметром, который вы уполномочены документировать. Сбор данных остаётся почти полностью пассивным/публичным (RDAP, DNS, логи CT — данные, уже публично раскрытые целью или её регистратором), за исключением traceroute (лёгкое активное действие, всегда отображаемое в используемом профиле).

**Ни одно наблюдение не начинается для незакреплённой цели без явного подтверждения** (`--authorize` в CLI, подтверждение в TUI). Вы несёте единоличную ответственность за соответствие вашего использования применимому законодательству и условиям использования сторонних источников.

## 2. Установка

### Требования

- Python 3.10+
- Подключение к Интернету — для зависимостей и опрашиваемых пассивных источников
- Установленный `traceroute` или `tracepath` (модуль NeoTrace) — при отсутствии корректно деградирует, остальная часть инструмента работает как обычно

### Установка

```bash
[ -d omega-track ] && echo "ℹ️ Уже распаковано здесь, шаг пропущен." || tar -xzf omega-track.tar.gz
cd omega-track/
chmod +x install.sh
./install.sh
```

`install.sh`:

1. Создаёт виртуальное окружение `.venv`, если его ещё нет.
2. Устанавливает зависимости (`pip install -e .`, `pyproject.toml` остаётся единственным источником истины).
3. Делает `omega-track.sh` и `install.sh` исполняемыми.
4. Добавляет псевдоним `track` в `~/.bashrc` и `~/.zshrc` (без дублирования, если уже присутствует).

### Зависимости

Объявлены в `pyproject.toml` (без отдельного `requirements.txt`):
- `omega-lib`: общая библиотека набора (`ConfidenceLevel`, темы, определение терминала)
- `textual`: интерфейс TUI, темы, автоматическая адаптация к терминалу
- `dnspython`: прямое и обратное разрешение DNS
- `httpx`: запросы к RDAP/CT/архивам/BGP/VirusTotal/HIBP
- `maxminddb`: чтение локальных баз GeoIP (DB-IP Lite, MaxMind GeoLite2)
- `jinja2`: шаблонизация для HTML-экспорта
- Зависимости для разработки (`pip install -e ".[dev]"`): `pytest`, `pytest-asyncio`, `pytest-cov`, `pytest-httpserver`, `ruff`, `mypy`, `import-linter`

## 3. Использование

### Интерактивный режим (TUI)

Рекомендуется для повседневного использования — запускается без аргументов:

```bash
./omega-track.sh
```
если вы создали псевдоним, просто наберите `track` в терминале:
```bash
track
```

Процесс: заставка (закрывается любой клавишей или кликом) → главное меню (Цели / Трекер / Результаты / История / Дашборд / GeoIP / Источники с ключом / Настройки / Помощь) → ввод или выбор цели (явное подтверждение, если не закреплена) и выбор модулей сбора → наблюдение (индикатор и живой журнал сетевых операций, с возможностью отмены) → подробные результаты по вкладкам (Идентичность/DNS/Сеть-ASN/NeoTrace/Сертификаты/Архивы/Связи/Диагностика, экспорт) → история/дашборд/настройки из главного меню. Адаптация к терминалу (цвета, размер, структурная деградация) выполняется автоматически.

#### Горячие клавиши

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | Навигация между элементами экрана |
| `Tab` / `Shift+Tab` | Навигация между полями формы |
| `Esc` | Назад к предыдущему экрану (подтверждение выхода на главном экране) |
| `t` | Следующая тема (применяется сразу, без подтверждения) |
| `r` | Обновить определение терминала |
| `a` | Показать справку |
| `q` | Выйти (с подтверждением) |

### Скриптовый режим (CLI)

Любая подкоманда включает режим CLI:

```bash
# Цели
./omega-track.sh target add example.org --alias "витрина сайта" --tag prod
./omega-track.sh target list
./omega-track.sh target pin <target_id>

# Запуск и отслеживание наблюдения
./omega-track.sh track run <target_id> --module dns --module rdap --module neotrace --authorize
./omega-track.sh track status <run_id>
./omega-track.sh track show <run_id>
./omega-track.sh track replay <run_id> --authorize

# История
./omega-track.sh history list --target <target_id> --status completed --since 2026-01-01

# Экспорт — 6 форматов, 5 тем для HTML
./omega-track.sh export <run_id> --format html --theme omega-neon --redact contacts_only

# GeoIP
./omega-track.sh geoip status
./omega-track.sh geoip update --provider dbip

# Источники репутации с ключом (раскрытие условий показывается перед сохранением)
./omega-track.sh source list
./omega-track.sh source info virustotal
./omega-track.sh source configure virustotal <api_ключ>

# Настройки и очистка
./omega-track.sh config show
./omega-track.sh cleanup preview --older-than 30
./omega-track.sh cleanup run --older-than 30 --yes

# Локальная диагностика (версии, возможности, пути, статус GeoIP)
./omega-track.sh diagnostics
```

Любая подкоманда принимает `--json` для строго машиночитаемого вывода.

#### Коды завершения

| Код | Значение |
|---:|---|
| `0` | Успех (наблюдение завершено, `COMPLETED`) |
| `1` | Ошибка валидации (недопустимая цель, неизвестный формат экспорта, недопустимый переход состояния, отсутствует API-ключ...) |
| `2` | Цель не авторизована (не закреплена и без `--authorize`) |
| `3` | Ресурс не найден или источник недоступен (неизвестная цель/запуск, ошибка загрузки GeoIP) |
| `4` | Частичное наблюдение (`PARTIAL`) — не сбой, лишь часть модулей завершилась успешно |
| `5` | Неожиданная внутренняя ошибка |
| `130` | Прервано пользователем (`Ctrl+C`) |

### Допустимые форматы цели

```text
192.168.1.10                IPv4
2001:db8::1                 IPv6
example.org                 Домен
```

## 4. Модули сбора данных

| Модуль | Режим сбора | Включён по умолчанию | Требуется ключ |
|---|---|:---:|:---:|
| `dns` | Лёгкий активный (прямое разрешение) | да | нет |
| `reverse_dns` | Лёгкий активный (PTR) | да | нет |
| `rdap` | Пассивный публичный | да | нет |
| `neotrace` | Лёгкий активный (traceroute/tracepath) | да | нет |
| `certificate_transparency` | Пассивный публичный (`crt.sh`) | нет | нет |
| `archives` | Пассивный публичный (Wayback Machine) | нет | нет |
| `bgp` | Пассивный публичный (RIPEstat) | нет | нет |
| `virustotal` | С ключом пользователя | нет | да (бесплатный) |
| `hibp` | С ключом пользователя | нет | да (**платный** с 2022 года) |

Первые четыре модуля образуют ядро MVP (`dns`/`reverse_dns`/`rdap`/`neotrace`) и отмечены по умолчанию в форме запуска; следующие пять — опциональны и должны включаться явно. Источник без настроенного ключа никогда не приводит к сбою наблюдения: соответствующий модуль просто получает статус `SKIPPED`. Подробности по каждому источнику, квоты и лицензии: `docs/DATA_SOURCES.md`.

## 5. Архитектура

Omega-track построен по принципам **Clean Architecture** (domain / application / infrastructure / interfaces / ports / core / app / plugins), в соответствии с шаблоном набора `omega-` (см. `omega-check`/`omega-fold`) и проверяется `import-linter` при каждом изменении.

```text
src/omega_track/
├── domain/          Чистая бизнес-логика (цели, TrackRun/ModuleRun, findings, связи, профили...)
├── application/     Сценарии использования (commands/queries/оркестраторы фаз/политики)
├── ports/           Контракты, ожидаемые приложением (коллекторы, репозитории, экспортёры...)
├── infrastructure/  Конкретные реализации (dnspython/httpx/subprocess/maxminddb, SQLite, jinja2)
├── interfaces/      tui/ (Textual) и cli/ (скриптовый), со строгим функциональным паритетом
├── app/             Сборка (DependencyContainer, bootstrap, жизненный цикл)
├── core/            Сквозной словарь (версии, реэкспорты omega-lib)
└── plugins/         Опциональные модули с единственным источником (CT, архивы, BGP, VirusTotal, HIBP)
```

Правила проектирования:
- `domain/` никогда не обращается к сети и не выполняет ввод-вывод; `infrastructure/` выполняет сеть и ввод-вывод, никогда не оценивает.
- `interfaces/` только отображает, не содержит бизнес-логики — CLI и TUI вызывают строго одни и те же сценарии использования.
- 1 модуль сбора = 1 источник = 1 статус (`ModuleRun`): никогда два источника не агрегируются в один неоднозначный статус.
- Отсутствие отдельного поля никогда не считается ошибкой; только полная недоступность источника вызывает `SKIPPED`/`FAILED`.

## 6. Источники данных

| Источник | Поставщик | Ключ | Режим |
|---|---|:---:|---|
| Прямой/обратный DNS | Системный резолвер | нет | Лёгкий активный |
| RDAP | Bootstrap IANA → RIR/регистратор | нет | Пассивный публичный |
| Certificate Transparency | `crt.sh` (Sectigo) | нет | Пассивный публичный |
| Веб-архивы | Wayback Machine (Internet Archive) | нет | Пассивный публичный |
| BGP / сетевые анонсы | RIPEstat (RIPE NCC) | нет | Пассивный публичный |
| GeoIP | DB-IP Lite (по умолчанию) или MaxMind GeoLite2 | нет / да | Offline (локальная база) |
| NeoTrace | Локальный `traceroute`/`tracepath` | нет | Лёгкий активный |
| Репутация | VirusTotal | да (бесплатный) | С ключом |
| Репутация | Have I Been Pwned | да (платный) | С ключом |

Точная квота, лицензия и запасной вариант для каждого источника: `docs/DATA_SOURCES.md`. Ни один API-ключ никогда не отображается в логах, экспортах или экранах диагностики.

## 7. Политика достоверности

Каждое собранное поле несёт один из следующих уровней (общий для всего набора через `omega-lib`):

| Уровень | Значение |
|---|---|
| `VERIFIED` | Протокольный факт, наблюдаемый напрямую, не подделываемый целью (например, прямой ответ DNS, локальное измерение traceroute). |
| `DECLARED` | Значение, самостоятельно заявленное источником в поле, которое он полностью контролирует (например, данные RDAP, отображаемые регистратором) — правдоподобно, но может быть подделано по желанию. |
| `CORROBORATED` | Значение `DECLARED`, подтверждённое независимым признаком (например, домен, замеченный как минимум в двух разных логах Certificate Transparency). |
| `INFERRED` | Выведено на основе паттерна/эвристики, без явного заявления (например, общий ASN, использованный для предположения связи, никогда не повышается автоматически). |
| `UNKNOWN` | Нет пригодного признака либо он активно скрыт целью. |

Общий показатель достоверности наблюдения — вспомогательный ориентир для чтения, а не вердикт о безопасности.

## 8. Уровни сбора, авторизация и редактирование

Каждый профиль явно указывает характер своих действий (`CollectionMode`):

- **Offline**: проверка цели, локальный поиск GeoIP, корреляции по уже сохранённым данным, экспорты — без сети.
- **Пассивный публичный**: RDAP, публичный DNS, логи CT, архивы, BGP — третьей стороне передаётся только запрашиваемая цель, это неотъемлемое свойство протокола.
- **Лёгкий активный**: разрешение DNS, обратный DNS, traceroute — настроенный резолвер и каждый промежуточный маршрутизатор на пути видят запрос.
- **С ключом пользователя**: провайдеры, требующие ключ или применяющие квоты, активируются только после явной настройки и показанного раскрытия условий (квота, отправляемые данные).

**Механизм авторизации**: ни одно наблюдение не начинается для незакреплённой цели без явного подтверждения (`--authorize` в CLI, флажок в TUI). Закрепление цели авторизует её на постоянной основе для будущих наблюдений.

**Редактирование экспортов**: каждый экспорт принимает политику (`none`/`contacts_only`/`sensitive_only`/`strict`), которая маскирует чувствительные поля (в частности, контакты RDAP) в экспортируемом результате — локальное хранилище всегда сохраняет полные собранные данные. Подробности: `docs/PRIVACY.md`.

## 9. Совместимость с терминалами

TUI (Textual) автоматически определяет возможности терминала (эмулятор, размер) и соответствующим образом адаптирует структурную таблицу стилей (`complete`/`standard`/`reduced`/`mono`), без ручных флагов. Режим CLI всегда остаётся простым текстом, независимым от терминала. Политика общая для всего набора `omega-` (`omega-lib`, `terminal/policies.py`).

### Профиль по определённому эмулятору

| Эмулятор | Начальный профиль |
|---|---|
| Ghostty, Alacritty, WezTerm, Kitty | `complete` |
| Konsole, GNOME Terminal, Terminator, Xfce4 Terminal | `standard` |
| xterm, urxvt, современный SSH | `reduced` |
| Linux TTY, устаревший SSH | `mono` |
| Нераспознанный эмулятор | `reduced` (запасной вариант по умолчанию) |

### Профиль по размеру терминала

| Минимальный размер (столбцы × строки) | Потолок профиля |
|---|---|
| 120 × 32 | `complete` |
| 100 × 28 | `standard` |
| 80 × 24 | `reduced` |
| ниже | `mono` |

Итоговый выбранный профиль — **более ограничивающий из двух** (эмулятор и размер). Обновляется вживую клавишей `r`.

## 10. Экспорт

Отчёты генерируются в `var/exports/` по умолчанию (путь runtime привязан к каталогу проекта, `$OMEGA_TRACK_VAR_DIR` для переопределения), либо по указанному пути (`--output` в CLI, диалог в TUI). Имя файла с меткой времени, уникальное: `{метка_времени}_{цель}_{краткий_id}.{расширение}`.

| Формат | Содержимое |
|---|---|
| `json` | Полная структура наблюдения (`TrackRun` + findings + связи), источник истины, строго сериализуемый в JSON |
| `markdown` | Компактный отчёт для человека, читаемый вне терминала |
| `html` | Автономный веб-отчёт, 5 тем на выбор (`--theme`), граф связей Mermaid встроен inline |
| `csv` | Одна таблица на категорию finding |
| `dot` | Граф связей Graphviz, автономный файл |
| `mermaid` | Граф связей Mermaid, автономный файл |

## 11. История, очистка и повтор

Каждое наблюдение сохраняется (SQLite, `var/db/omega-track.db`): просматриваемая и фильтруемая история (цель/статус/тег/период), сводный дашборд (разбивка по статусам, надёжность по модулям, типология последних findings), повтор наблюдения для той же цели без повторного ввода данных (`track replay`), очистка старой истории с обязательным предварительным просмотром перед любым удалением (`cleanup preview` перед `cleanup run --yes`).

## 13. Вне области применения

- Полная история WHOIS/DNS, коммерческий passive DNS
- Поиск людей, соцсети, pastebin-утечки
- Сканирование портов, определение служб и баннеров (`omega-check`)
- Проверки HTTP/HTTPS, заголовков, TLS (`omega-scan`)
- Обход и анализ архитектуры (`omega-deep`/`omega-fold`)
- Нагрузочное тестирование (`omega-stress`), фаззинг (`omega-fuzz`)
- Интерактивная карта в TUI (зарезервирована для экспортированного HTML-отчёта)
- Непрерывный, многозондовый, многоточечный MTR
- Пакетный/периодический/повторяющийся режим наблюдения за целью — `TrackRun` всегда остаётся явным ручным действием
- Движок миграции схемы SQLite до версии 1.0 (аддитивная схема, та же практика, что и в остальном наборе)
